Command (Slither 0.11 via `uv tool install slither-analyzer`, Foundry build):

```
cd contracts && slither . --filter-paths "lib/|test/|script/" --exclude-dependencies
```

31 contracts, 102 detectors, 33 results. Every result was read against the code; none required a change before the testnet deploy. Two hardening items are queued for the mainnet release (v5) because any contract edit means a redeploy on both testnets.

| Impact | Detector | Where | Verdict |
|---|---|---|---|
| High | reentrancy-balance | `depositWithAuthorization`: balance read before `receiveWithAuthorization`, delta checked after | **False positive.** The balance delta is the fee-on-transfer-safe way to learn what arrived; the function is `nonReentrant`, and the token is owner-allow-listed (USDC / pathUSD). A reentrant call cannot change the delta's meaning. |
| Medium | incorrect-equality (2) | `received == 0` in `deposit` and `depositWithAuthorization` | **False positive.** A zero-check on a computed delta, not a balance equality. |
| Medium | reentrancy-no-eth (6) | `settle`, `autoSettle`, `resolve`, `refundExpired`, `_payout`, `_deployToEarn`: Earn vault calls (`withdrawExact` / `redeem` / `deposit`) precede `job.status` and `balances` writes | **Accepted, guarded.** Every entrypoint that reaches an Earn vault is `nonReentrant` (`fund`, `settle`, `settleWithSig`, `autoSettle`, `resolve`, `refundExpired`, the Earn and Zone functions). The unguarded functions (`submit`, `dispute`, `resubmit`, `attest`, `attributeDeposit`, `createJob`) make no external calls and are party- or role-gated, so a venue cannot reach them mid-call. Earn vaults are owner-allow-listed. **v5:** move the `job.status` write before `_payout` / `_recall` so the order is checks-effects-interactions even without the guard. |
| Medium | unused-return (2) | `_withdrawToZone` ignores `depositEncrypted`'s `newCurrentDepositQueueHash` | **Accepted.** The queue hash is the portal's bookkeeping; the Vault records the transfer in `WithdrawnToZone`. |
| Low | missing-zero-check (4) | `arbiter` / `intake` in the constructor and setters | **v5:** add `ZeroAddress` checks. Owner-only today; a zero arbiter would only block `resolve` until reset. |
| Low | reentrancy-benign (8) | event emission after Earn / portal calls | Same guard argument as above; events only. |
| Low | timestamp (4) | deadlines (`submitDeadline`, `reviewWindow`, signature `deadline`) | **Accepted.** Windows are hours to days; validator drift of seconds is immaterial. |
| Info | assembly, naming-convention, unindexed-event-address (4) | `_useSig` selector check; event params | Style. `EarnRedeemed` / `EarnDeposited` keep the vault address unindexed on purpose (three indexed slots are used). |
